# AI 协作最佳实践指南 (Best Practices for AI Collaboration)

通过我们在 **Lead-to-Cash (L2C)** 项目中的合作，我总结了一套高效提问与协作的“最佳实践”。遵循这些原则，您可以获得更精准、高质量的代码和解决方案。

## 1. 核心公式：上下文 + 目标 + 如果/那么 (Context + Goal + Constraints)

最有效的提示词通常包含这三个要素。

*   **❌ 模糊的提问**：
    > "帮我改一下发票页面。"
*   **✅ 精准的提问**（参考您的树状图需求）：
    > "把合同作为第一列，发票作为子项，列出像一个树一样。"
    *   **上下文**：当前是列表页。
    *   **目标**：改为树状结构 (Contract -> Invoice)。
    *   **结果**：层级展示。

## 2. 视觉辅助胜过千言万语 (Visuals are Powerful)

在涉及 UI/UX 问题时，截图是最直接的沟通方式。

*   **案例回顾**：
    *   您上传了侧边栏高亮的截图，问 "为啥有2个选中"。
    *   如果您只说 "侧边栏高亮有问题"，我可能需要查很久日志。但看到截图，我立刻意识到是路由匹配逻辑太宽泛 (Regex/Prefix match)。
*   **建议**：
    *   遇到 UI 错位、样式问题，**直接贴图**。
    *   圈出有问题的地方（就像您做的那样）。

## 3. 分步迭代，而非一步登天 (Iterate, Don't Overwhelm)

复杂的任务如果一次性丢给 AI，容易导致上下文丢失或逻辑混乱。将大任务拆解为小步骤效果更好。

*   **我们的成功路径**：
    1.  **第一步**：先增加侧边栏入口 "Invoice Management"。
    2.  **第二步**：将卡片视图重构为表格视图 (Table View)。
    3.  **第三步**：优化排序逻辑（按项目分组）。
    4.  **第四步**：最终重构为树状表格 (Tree View)。
*   **建议**：
    *   不要试图在一个 Prompt 里完成整个系统的重构。
    *   建立一个 Checkpoint（如我们现在的状态），确认无误后再进行下一步。

## 4. 提供具体的报错信息 (Be Specific with Errors)

*   **❌ 模糊的反馈**：
    > "数据不对。"
*   **✅ 有效的反馈**：
    > "Pending Invoice Amount 显示为 0，但我已经有 Verified 的里程碑了。"
*   **原理解析**：这让我能迅速定位到 `finance.service.ts` 中的计算逻辑，直接排查状态枚举值 (Status Enum) 是否匹配。

## 5. 引用现有代码/模式 (Reference Existing Patterns)

如果您希望新功能保持一致性，可以明确指出参考对象。

*   **示例**：
    > "请参考 `Project Delivery` 页面的 KPI 卡片样式，在 `Finance` 页面也加一组类似的指标卡片。"
*   这能确保设计语言（Design System）的一致性，减少反复修改样式的工时。

## 6. 提示词模板 (Prompt Templates)

### 🐛 修复 Bug
> **现象**：[描述发生了什么，例如：侧边栏两个菜单同时高亮]
> **期望**：[描述应该发生什么，例如：只有当前子菜单高亮]
> **参考截图**：[附图]
> **相关文件**：[如果知道，提供文件名，例如 Sidebar.tsx]

### ✨ 新功能开发
> **目标**：[一句话描述功能，例如：实现发票列表的树状折叠]
> **数据结构**：[描述层级，例如：合同是父级，发票是子级]
> **交互细节**：[例如：默认全部展开，支持搜索过滤]

### 💅 UI 调整
> **目标**：[例如：把表格的行高调小一点]
> **参考风格**：[例如：参考 Shadcn UI 的 compact 模式]
